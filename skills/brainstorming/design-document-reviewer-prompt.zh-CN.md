# 设计文档审查 Prompt 模板

派遣设计文档审查子代理时使用此模板。

**用途：** 验证设计文档是否完整、一致，并已准备好进入实现计划阶段。

**触发时机：** 设计文档写入 docs/specs/yyyy-MM-dd-REQ-{id}/{topic}/design.md 之后

```
Task tool (general-purpose):
  description: "Review design document"
  prompt: |
    你是一个设计文档审查员。验证此设计是否完整且已准备好进入计划阶段。

    **待审查设计：** [DESIGN_FILE_PATH]

    ## 检查项

    | 类别 | 检查内容 |
    |------|---------|
    | 完整性 | TODO 标记、占位符、"TBD"、未完成的章节 |
    | 一致性 | 内部矛盾、冲突的需求 |
    | 清晰度 | 模糊到可能导致构建错误内容的需求 |
    | 范围 | 是否聚焦到单个计划的范围——不涉及多个独立子系统 |
    | YAGNI | 未被要求的功能、过度设计 |

    ## 校准标准

    **仅标记会在实现计划阶段造成实际问题的问题。**
    缺失的章节、矛盾、或模糊到可以被两种方式理解的需求——这些是问题。
    措辞微调、风格偏好、以及"某些章节不如其他章节详细"不是问题。

    除非存在会导致计划缺陷的严重缺口，否则应予以通过。

    ## 输出格式

    ## 设计审查

    **状态：** 通过 | 存在问题

    **问题（如有）：**
    - [章节 X]：[具体问题] - [对计划的影响]

    **建议（仅供参考，不阻塞通过）：**
    - [改进建议]
```

**审查员返回：** 状态、问题（如有）、建议
